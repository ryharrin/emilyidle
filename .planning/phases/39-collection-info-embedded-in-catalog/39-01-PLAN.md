  <name>Task 1: Add a Catalog header collection context block (VLT-01, VLT-02)</name>
  <files>src/ui/tabs/CatalogTab.tsx, src/ui/catalog/collectionContext.ts</files>
  <action>
  - Create `src/ui/catalog/collectionContext.ts` exporting a small, pure helper for the Catalog UI:
    - `getCatalogCollectionContext(state: GameState): { ownedCount: number; maxCapacity: number; collectionValueCents: number }`.
    - `ownedCount` must be computed via `getTotalItemCount(state)`.
    - `collectionValueCents` must be computed via `getCollectionValueCents(state)`.
    - `maxCapacity` is display-only, derived from the *next not-yet-unlocked* milestone threshold where `milestone.requirement.type === "totalItems"`.
      - Use `getMilestones()` and `state.unlockedMilestones`.
      - Choose the smallest `threshold` that is `> ownedCount` and whose milestone id is not in `state.unlockedMilestones`.
      - If no such milestone exists, set `maxCapacity = ownedCount` (still display-only; do not change purchase semantics).
  - In `src/ui/tabs/CatalogTab.tsx` (in `CatalogPurchasePanel`):
    - Import and call `getCatalogCollectionContext(state)`.
    - Render a compact pill inside `.catalog-header-actions` showing:
      - `Collection: {ownedCount} / {maxCapacity}` (use the existing `formatCount` formatting in this component).
      - `Collection value: {formatMoneyFromCents(collectionValueCents)}`.
    - Add a stable selector for tests: `data-testid="catalog-collection-context"` on this pill.
  - Guardrails (must not change):
    - Do not add any new purchase gating and do not change `buyWatchModel` usage.
    - Do not change existing `id` or `data-testid` values (especially `catalog-buy-*`, `catalog-gate-*`, and `vault-interact-*`).
  </action>
  <verify>pnpm run typecheck && pnpm -s exec rg "catalog-collection-context" src/ui/tabs/CatalogTab.tsx</verify>

  </done>
