  <action>
Add bounded, decaying progressive session premium tracking.

Implementation shape (keep selectors/actions pure; pass/consume nowMs explicitly):
- Extend therapist career state with two fields:
  - `sessionPremiumCount: number` (>=0)
  - `lastSessionAtMs: number` (>=0; 0 for never)
- Update `createInitialState()` (or equivalent) to initialize these fields.
- Update save load/sanitize in `src/game/persistence.ts` to accept missing fields from older saves and normalize to safe defaults.

Policy rules (can be adjusted during implementation, but keep the invariants):
- Premium triggers when sessions are repeated within a "premium window" (recommended: `windowMs = cooldownMs * 2`).
- Premium is bounded (recommended: cap at 2-3 increments).
- Each increment adds a fixed enjoyment cost multiplier step (recommended: +20% per increment) and is visible in UI.
- Premium decays: when `nowMs - lastSessionAtMs >= windowMs`, reset `sessionPremiumCount` back to 0.

Wire into the session cost:
- In `getTherapistSessionPolicy(state)`, compute and expose:
  - `baseEnjoymentCostCents`
  - `premiumMultiplier` (1.0..cap)
  - `premiumEnjoymentCostCents` (final cost)
  - `premiumLabel` (e.g. "Second session premium")
  - `premiumNote` (short explanation suitable for UI)
- Keep `canPerformTherapistSession(state, nowMs)` driven by the final computed enjoyment cost (or use the new policy field).

Update `performTherapistSession(state, nowMs)`:
- Clamp nowMs (finite, integer, >=0).
- Update `lastSessionAtMs` to nowMs.
- Update `sessionPremiumCount`:
  - If prior `lastSessionAtMs` is within window: increment (clamped to cap)
  - Else: reset to 0 before applying the post-session increment rule (so a "fresh" session starts premium-free)

Add unit coverage:
- Consecutive sessions within the window increase the premium enjoyment cost (up to cap).
- After waiting beyond the window, premium resets back to baseline.
- Loading a save missing the new fields results in valid default values and does not throw.
