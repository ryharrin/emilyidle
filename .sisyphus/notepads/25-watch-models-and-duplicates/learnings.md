# Learnings

## 2026-01-28

### Reference curves / player-facing rules

- EVE Online stacking penalties (stacking multiple similar bonuses): provides both a concrete formula and a “numbers table” that players commonly internalize.
  - Formula: “The n-th modifier is multiplied by S(n-1) … S(u)=e^{-(u/2.67)^2}”.
  - Rounded guidelines: 1st=100.0%, 2nd≈86.9%, 3rd≈57.1%, 4th≈28.3%, 5th≈10.6%, 6th≈3.0%.
  - Source: https://wiki.eveuniversity.org/index.php?title=Stacking_penalties&oldid=224087

- WoW crowd-control DR (successive applications): simple, discrete tiers that are easy to message as “half / quarter / immune”.
  - Default DR sequence encoded as {0.50, 0.25} with comment “immune at the 4th application”.
  - API docs show player-facing semantics: GetNextDR(1) => 0.50 (half), GetNextDR(2) => 0.25 (quarter), GetNextDR(3) => 0.00 (immune).
  - Evidence: https://github.com/wardz/DRList-1.0/blob/53669f7d561aeb915d14f90bb7e4c72f9ea85a81/DRList-1.0/DRList-1.0.lua#L317-L374

### Phase 25 UI copy recommendations (duplicates)

- Prefer messaging the “next copy” explicitly, not just the total: e.g. “Next copy: +0.34x (70% of previous)” or “Next copy effective at 57%”.
- Consider either:
  - Discrete tiers (WoW-style) if you want maximum clarity: 100% / 50% / 25% / 0%.
  - Smooth stacking penalty (EVE-style) if you want softer falloff: 100% / 87% / 57% / 28% …
- Tooltip pattern that reduces confusion: show a short table “Copy 1: 100%, Copy 2: 70%, Copy 3: 49% …” and a computed “Total duplicate multiplier”.

### Implementation notes (Plan 25-01)

- When deriving a stable roster from `CATALOG_ENTRIES`, per-brand reference numbers can be generated by counting entries in catalog order within each brand (deterministic, no extra data needed).
- Save restore for sparse maps should whitelist keys (e.g., known model ids) and clamp values to finite integers >= 0 to avoid corrupt/hostile saves.
